# 知识网络与引导式学习设计

本原型在 WeKnora 的 Wiki 中提供个人练习、学习状态和下一主题推荐。用户阅读知识页面后，可以生成带来源引文的测验；服务端按已校验的答案判分，更新掌握度估计，再据此推荐练习或复习。现有长期记忆只参与兴趣匹配和熟悉度判断。

## 节点与信号

知识节点采用 `WikiPage.ID`，粒度为 Wiki 页面。可练习节点限于已发布的 `entity`、`concept`、`synthesis` 和 `comparison` 页面，并要求有当前有效的来源文档与分块。页面重命名保留 ID 和学习历史，Wiki 链接只表示相关主题，不推断先修关系。

| 信号 | 来源 | 用途 |
| --- | --- | --- |
| 页面访问 | 当前用户明确打开的 Wiki 页面 | 标记「已接触」，不增加掌握度 |
| 文档亲和度 | 长期记忆已有的来源文档引用统计 | 在记忆与个性化开关允许时标记熟悉节点 |
| 兴趣 | 当前用户的长期记忆检索上下文 | 与页面标题、别名匹配，参与推荐排序 |
| 测验作答 | 服务端验证并持久化的选择题答案 | 更新 BKT 掌握度与复习时间 |
| 页面与分块版本 | 实际内容、来源集合、模型及提示词版本 | 判断测验和掌握度是否需要重新评估 |

学习功能默认关闭，授权与长期记忆相互独立。关闭记忆后，阅读、练习和非个性化推荐仍可使用。

## 掌握度

使用贝叶斯知识追踪（BKT）进行确定性更新。每个节点初始掌握概率为 `0.20`，学习转移概率 `0.15`，猜对概率 `0.25`，失误概率 `0.10`。观察一次答案后先做贝叶斯更新，再应用学习转移：

```text
答对：posterior = p * 0.90 / (p * 0.90 + (1 - p) * 0.25)
答错：posterior = p * 0.10 / (p * 0.10 + (1 - p) * 0.75)
next_p = posterior + (1 - posterior) * 0.15
```

至少取得三道不同有效题目的计分，且 `p >= 0.85`，才显示「已掌握」。同一用户、同一页面、同一来源版本下的相同规范化题干只取得一次计分；来源版本变化后允许重新评估。重复提交相同 attempt 返回原结果，冲突提交返回错误。阅读次数、模型评价和 Agent 对话不会增加掌握度。

复习间隔采用 1、3、7、14、30 天。页面或来源内容变化后，旧测验不可继续作答，当前掌握度回到先验值等待新评估；普通编辑保留历史作答。来源被删除或移出范围时，相关测验及答案会被清除，防止导出已撤回的来源内容。

这些参数未经真实学习者校准。概率是固定模型的估计值，不能作为能力认证或学习收益的证据。

## 出题与证据

每次生成三道四选一题。输入限于当前页面和同租户、同知识库的有效来源分块，不包含用户兴趣、个人档案或历史答案。

生成结果需通过结构检查、选项与答案索引检查、来源归属检查，以及引文在原文中的连续匹配。随后以同一模型的新对话盲答，旋转选项顺序且不提供生成答案或解析，检查生成答案与盲答的一致性。任一检查失败则题集失败，不发布部分合格题目。

题目、选项和来源由模型生成，判分和状态更新由服务端执行。未作答 DTO、导出及 Agent 工具结果不携带答案。Agent 只得到可重新加载的测验卡片引用，不能替用户授权、答题或修改掌握度。

同模型盲答存在相关性偏差，无法证明题目正确。实际使用仍需核对引文；提交材料分别报告真实模型链路和合成算法评估，不混合两者。

## 推荐与呈现

推荐分数由以下四项组成：

```text
0.45 * review_need
+ 0.25 * graph_frontier
+ 0.20 * interest_match
+ 0.10 * content_quality
```

候选来自当前知识库的合格页面，数量有上限。排序使用稳定的 ID 次序处理同分，并保留探索位置、页面类型多样性；到期复习优先于类型多样性。已掌握且未到复习时间的节点不进入推荐。界面显示推荐原因，用户可以跳转阅读或准备测验。

Wiki 面板提供概览、推荐、练习及学习数据操作。Graph 叠加「未评估 / 学习中 / 已掌握 / 待复习」状态和独立熟悉度标记。内置学习 Agent 可以读取概览、推荐主题和准备测验卡片，卡片从学习 API 获取权威状态。

## 持久化与隔离

学习状态以数据库为准，PostgreSQL 为服务端部署主存储，SQLite 兼容 Lite。Asynq 只负责触发任务；入队失败不会丢失已经持久化的 pending 测验。任务通过稳定 TaskID、恢复派发冷却、租约、认领令牌和超时恢复防止队列膨胀或重复发布，不跨模型调用持有事务。

个人作用域由已认证 Web 用户和执行租户共同确定。API Key、IM、嵌入客户端、共享 Agent 和跨工作区共享知识库不纳入本原型范围。生成、读取、发布、判分、导出均检查作用域与来源有效性。

判分、attempt 记录和 mastery 更新在同一事务中完成。关闭或清空会递增 profile epoch，使旧 worker 无法恢复已撤销数据。清除单个知识库保留其他知识库历史，但使同一档案内其他未完成测验过期。

用户可关闭学习、查看本人状态、导出及删除所选知识库或工作区的个人学习数据。普通请求日志和模型追踪不记录答案正文；内部数据库错误只记录受限诊断分类。

## 验证方式

算法评估使用版本固定、带 SHA-256 的合成数据集，覆盖推荐排序、状态转换、BKT 算术和留出答案预测。推荐与节点度数、冷启动基线对比；BKT 与固定猜测和固定先验对比。数据量小且为合成构造，仅作为回归测试，不推导真人效果。

工程验证包含 PostgreSQL/SQLite 事务及 race 测试、授权和来源清理测试、前端状态竞态测试，以及一次性账号上的真实模型 API 和浏览器流程。执行命令、实际结果、跳过项和局限见同一提交包中的验证记录。

- `internal/types/learning_algorithm.go`：BKT、复习状态与题干指纹
- `internal/agent/tools/learning.go`：学习工具
- `frontend/src/views/knowledge/wiki/LearningPanel.vue`：学习面板
